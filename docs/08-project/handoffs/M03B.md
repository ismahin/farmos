## Objective and result

Made the existing M03 opaque, revocable PostgreSQL session safely consumable by the Next.js browser without moving identity, tenant, roles, permissions, or farm authority into client state. M04 and future domain work were not started.

## Browser session transport

`POST /api/v1/auth/login` and bootstrap registration retain their default bearer response for non-browser compatibility. A browser sends `X-Session-Transport: cookie`; the API sets the opaque token as `farmos_session` and omits it from JSON. The cookie is HttpOnly, SameSite=Lax, scoped to `/api`, and carries explicit Max-Age/expiry. It is Secure whenever `NODE_ENV=production`; production also refuses to start without an HTTPS-only exact `WEB_ORIGINS` allowlist.

The cookie contains only the random opaque session credential. The database stores only its SHA-256 hash. Login always creates a fresh random session, preventing adoption of a caller-chosen session identifier. Logout revokes the persisted session before expiring the cookie. Expired, revoked, disabled-user, suspended-membership, and suspended-tenant sessions fail server-side resolution.

## CSRF and CORS

SameSite=Lax is defense in depth. Cookie-transport login/register and all unsafe cookie-authenticated requests require an `Origin` exactly present in `WEB_ORIGINS`; missing or foreign origins return 403 Problem Details. Safe reads do not require Origin. Bearer automation without an Origin remains compatible.

Nest CORS enables credentials only for the configured exact origins and allowlists methods/headers required by current APIs. Wildcard credentialed CORS is not used. Production assumes an HTTPS same-site web/API topology; cross-site cookie deployment is unsupported without a later security decision.

## `/me` authority

`GET /api/v1/me` now returns only safe client context:

- user ID, display name, email;
- tenant ID and display name resolved from the session;
- effective permission codes resolved by the backend;
- owner/all-farms scope and up to 100 accessible farm summaries with `truncated`.

Clients cannot choose tenant via headers, payloads, queries, or selected farm. Farm resource endpoints continue enforcing tenant, permission, and assignment scope independently.

## Configuration

- `WEB_ORIGINS`: exact comma-separated origins; defaults to `http://localhost:3000` outside production and is mandatory HTTPS-only in production.
- `SESSION_COOKIE_NAME`: optional, defaults to `farmos_session`.
- Existing `SESSION_TTL_HOURS` drives both database expiry and cookie Max-Age.

Local configuration is documented in `docs/09-operations/LOCAL_DEVELOPMENT.md`. No runtime dependency or database migration was added.

## API/OpenAPI

The executable OpenAPI describes bearer/cookie transport response variants and the expanded `/me` response. Authoritative browser instructions are in `docs/04-contracts/M04_AUTH_INTEGRATION.md`; M04 must use `credentials: "include"` and must not use the bearer response or JavaScript-readable credential storage.

## Security review

- Session fixation: fresh server-generated token per login.
- XSS credential exposure: HttpOnly; cookie transport response omits token.
- CSRF: exact Origin enforcement plus SameSite=Lax.
- CORS: exact allowlist with credentials; no wildcard.
- Cookie scope: `/api`, explicit lifetime, Secure in production.
- Logout/disabled/expiry: server-side resolution and tests.
- Tenant/farm/role injection: ignored or rejected; authoritative context remains server-side.

## Known limitations

Public signup/invitations, password recovery/change, email verification, MFA, session/device management UI, rate limiting, and external OIDC remain deferred. Bootstrap secrets must never enter a public frontend bundle. Production reverse-proxy/TLS configuration is operational work.
