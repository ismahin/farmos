## Authoritative decisions

- **Backend:** Node.js 24 LTS, strict TypeScript, NestJS, Drizzle ORM/Kit + `pg`; transaction-scoped parameterized SQL is allowed inside module-owned repositories for RLS/locking/specialized PostgreSQL work; Vitest, Nest testing/Supertest and real-PostgreSQL Testcontainers; OpenTelemetry. No optional framework/package is mandated without need.
- **Database:** PostgreSQL transactional truth, module schemas in one database, typed relational facts, controlled JSONB, UUIDv7, UTC `timestamptz`, decimal Money/Quantity with currency/UOM.
- **Tenancy:** shared database; trusted authenticated tenant context only; explicit application predicates/authorization plus tenant-scoped constraints/composite FKs and forced RLS. Runtime role cannot own/bypass RLS.
- **Modules:** modular monolith with owned tables and public application contracts. Common Production/Catalog/Inventory/Finance/Traceability do not depend on Poultry. No arbitrary cross-module table access.
- **Production:** common ProductionCycle is the time-bounded biological/economic core and freezes a resolved blueprint snapshot when started.
- **Inventory/finance/history:** append-only stock ledger and immutable posted journal with reversal/adjustment; relational current state plus operational FarmEvent/audit/outbox—not universal event sourcing.
- **API/eventing:** REST/OpenAPI `/api/v1`, Problem Details, cursor pagination, ETags, idempotency/correlation; transactional outbox and idempotent inbox consumers; RabbitMQ only when consumers exist.
- **Security/AI:** RBAC + contextual ABAC, generic versioned approval/HITL, tamper-resistant audit. Hermes is a replaceable orchestrator through FarmOS-owned authenticated tools; no SQL/internal-HTTP/tenant override.
- **Testing:** real PostgreSQL integration tests, two-tenant negative matrix, concurrency/idempotency/reconciliation, architecture dependency tests and the golden poultry E2E.
