## Objective and result

Implemented the first production backend foundation and proved the complete fresh-database → bootstrap owner → authenticate → organization/farms → second user/role/farm scope → denied unauthorized/cross-tenant access → audit journey against real PostgreSQL. M04 and all future ERP domains were not started.

## Runtime and workspace

- Node.js 24 LTS, npm workspaces, strict TypeScript, NestJS 12.0.4.
- Drizzle ORM 0.45.3/Kit 0.31.11 with `pg` 8.23.0.
- Backend root: `apps/api`; module internals use `api`, `application`, `domain`, and `infrastructure`, with intentional public persistence entry points.
- Modules: `PlatformModule`, `IdentityModule`, `OrganizationModule`, `FarmModule`; narrow database, audit, idempotency, event, HTTP, health, tenancy, ID, and observability building blocks.

## PostgreSQL and migration

`apps/api/drizzle/0000_m03_foundation.sql` creates `platform`, `identity`, `organization`, `farm`, `audit`, and `integration`. It contains tenant/entitlement, user/membership/role/permission/session/farm assignment, organization/legal entity, farm, immutable audit, idempotency, and unpublished outbox storage.

The DDL role owns/applies migrations. `farmos_runtime` is `NOLOGIN`, `NOBYPASSRLS`; deployments create a login that inherits it. Tenant tables have enabled and forced RLS. Policies compare `tenant_id` to transaction-local `app.tenant_id`. `DatabaseService.runInTenantTransaction` acquires one pool connection, begins one transaction, parameterizes `set_config(..., true)`, performs business/audit/outbox work, then commits or rolls back. Composite tenant foreign keys reject cross-tenant references.

## Authentication and authorization

Passwords use Argon2id. Registration requires the configured `X-Bootstrap-Token` and atomically creates a tenant, owner membership, entitlement, and seeded Tenant Owner/Farm Manager/Worker roles. Login returns a random opaque bearer token; only its SHA-256 hash is persisted. Sessions expire, revoke on logout, and are rejected for disabled user/membership/tenant state.

The server resolves user, tenant, session, and effective permissions through constrained security-definer lookup functions. Client tenant fields/headers are ignored or DTO-rejected. The global guard is deny-by-default: only explicitly public routes bypass authentication; protected actions declare permissions. Non-owner farm reads/updates additionally require `FarmAssignment`; tenant owners have tenant-wide farm scope.

## Cross-cutting foundations

- Audit records include tenant, actor, action, entity, time, correlation, source, and structured change; runtime can select/insert only, and a trigger rejects update/delete.
- PostgreSQL idempotency records fingerprint canonical payloads; same request replays, changed payload conflicts, and concurrent duplicates serialize to one logical result.
- Organization/Farm creates persist aggregate, audit, and versioned outbox record atomically. No publisher/broker exists yet.
- Organization/Farm updates use numeric ETags/`If-Match` and reject stale writes with 412.
- RFC-style `application/problem+json`, bounded cursor farm pagination, validated DTOs, UUIDv7 aggregate IDs, and request correlation are wired globally.

## API and OpenAPI

Implemented routes are recorded in `docs/04-contracts/M03_API.md`. Runtime Swagger UI is `/api/docs`; health probes are `/api/v1/health/live` and `/api/v1/health/ready`.
