## Executive Summary

Milestone **M04** has successfully replaced the provisional M01 mock SaaS/account context with the authoritative **M03/M03B backend APIs** while preserving the existing FarmOS application shell and UX patterns. 

Authentication is now backed by real HttpOnly browser session cookies (`POST /api/v1/auth/login`, `GET /api/v1/me`, `POST /api/v1/auth/logout`) with zero JavaScript-readable credential storage. Organization profile, farm management, team memberships, role assignments, farm assignments, and audit logging are fully connected to real backend endpoints using `If-Match` ETags for optimistic concurrency and `Idempotency-Key` headers for safe command retries.

All downstream operational modules (Production, Stock, Purchasing, Sales, Money, Analytics, and AI Assistant) remain untouched, stable, mock-backed prototypes.

## Completed Scope

### 1. Typed API Client Layer (`apps/web/lib/api/`)
- **`types.ts`**: TypeScript definitions matching M03 DTOs and view models (`MeResponse`, `UserSummary`, `TenantSummary`, `AccessibleFarmSummary`, `FarmView`, `CreateFarmRequest`, `UpdateFarmRequest`, `OrganizationView`, `CreateOrganizationRequest`, `UpdateOrganizationRequest`, `UserView`, `CreateUserRequest`, `RoleView`, `AuditRecordView`, `ProblemDetails`).
- **`errors.ts`**: `ApiProblemError` conforming to RFC 9457 / FarmOS Error Contract. Provides typed access to `status`, `code`, `title`, `message`, `correlationId`, and `fieldErrors`.
- **`client.ts`**: Base `apiFetch<T>` enforcing `credentials: "include"`, automatically transmitting `Idempotency-Key` and `If-Match` headers, capturing `ETag` response headers, and parsing Problem Details errors.
- **Domain API Modules**:
  - `authApi`: `login` (with `X-Session-Transport: cookie`), `logout`, `getMe`.
  - `organizationsApi`: `get`, `create`, `update` (with `If-Match`).
  - `farmsApi`: `list` (cursor paginated), `get`, `create` (with `Idempotency-Key`), `update` (with `If-Match`).
  - `usersApi`: `list`, `create`, `assignRole`, `assignFarm`.
  - `rolesApi`: `list`.
  - `auditApi`: `list`.

### 2. Browser Session & Auth Context (`apps/web/components/shell/`)
- **`AuthProvider` & `useAuth` (`auth-context.tsx`)**:
  - Connects to `GET /api/v1/me` upon bootstrap; supports manual session refresh.
  - Exposes authoritative `user`, `tenant`, `permissions`, `accessibleFarms`, and `currentFarm`.
  - Resolves `currentFarm` based on user's client-side UX preference in `localStorage` validated against server-returned `accessibleFarms`.
  - Permission evaluation helpers: `hasPermission(code)` and `hasAnyPermission(codes)`.
  - Differentiates `401 Unauthorized` (clears local cache, navigates to `/login`) from `403 Forbidden` (retains session, exposes notice with correlation ID).
- **`AuthGuard` (`auth-guard.tsx`)**:
  - Displays accessible loading skeleton during initial session bootstrap (preventing hydration mismatch and redirect loops).
  - Protects `/(erp)` routes by redirecting unauthenticated users to `/login`.
  - Displays a dismissible top banner with `correlationId` upon encountering a 403 Forbidden action.
- **`RootLayout` Integration (`app/layout.tsx`)**:
  - Wraps application tree in `AuthProvider` for unified context across auth and ERP routes.

### 3. Application Shell & Header (`components/shell/`)
- **Header (`header.tsx`)**:
  - Displays authoritative `tenant.displayName`.
  - Farm selector dropdown renders only server-returned `accessibleFarms`.
  - Links to compose a new farm are gated by `auth.hasPermission("farm.create")`.
  - Replaced prototype persona switcher with real user menu displaying user name, email, tenant name, active permissions summary, and an explicit **Sign Out** button calling `auth.logout()`.
- **Shell Context (`context.tsx`)**:
  - Consumes `AuthProvider`, safely mapping server-backed tenant and accessible farms to UI shapes with fallback structures for mock pages.

### 4. Page Integrations (`app/`)
- **Login Page (`app/(auth)/login/page.tsx`)**:
  - Sends real HTTP POST to `/api/v1/auth/login` with `X-Session-Transport: cookie`.
  - Handles Problem Details errors with user-friendly notices and correlation ID display.
  - Redirects authenticated users to `/`.
  - Replaced fake persona mock buttons with development pre-fill helpers.
- **Farms Directory (`app/(erp)/farms/page.tsx`) & Detail (`[id]/page.tsx`)**:
  - Displays real accessible farms list.
  - Gated "+ Compose New Farm" button via `farm.create` permission.
  - Displays `EmptyState` if no accessible farms are assigned.
- **Settings Page (`app/(erp)/settings/page.tsx`)**:
  - **Organization Tab**: Connects to `GET /api/v1/organizations/:id` and `PATCH /api/v1/organizations/:id` with `If-Match` ETag and `organization.manage` permission gating. Handles 412 Concurrency Conflicts.
  - **Farms Tab**: Lists real farms, includes "+ Add Farm" modal with `Idempotency-Key` and "Edit Farm" modal with `If-Match`. Gated by `farm.create` and `farm.update`.
  - **Users & Roles Tab**: Lists real users and roles. Includes "+ Add Member" modal with temporary password, "Assign Role" modal, and "Assign Farm" modal. Gated by `users.read`, `users.manage`, `roles.read`, `roles.manage`.

## Architectural & Security Guardrail Adherence

- **HttpOnly Cookies Only**: All auth session tokens are stored exclusively in HttpOnly cookies managed by the browser; zero auth tokens or passwords exist in `localStorage` or JavaScript state.
- **Server-Side Authorization Authority**: Client permissions and roles are strictly derived from `/api/v1/me`. No component fabricates permissions. Selecting a farm in the UI is treated solely as a UX query preference, rechecked on the backend.
- **Optimistic Concurrency**: Material updates (Organization displayName, Farm displayName/timezone) require and transmit server `If-Match` ETags.
- **Idempotency Protection**: Entity creation endpoints (Farms, Organizations) send unique `Idempotency-Key` headers.
- **Problem Details & Correlation**: All client errors preserve RFC 9457 fields (`status`, `code`, `message`, `correlationId`, `fieldErrors`).
- **No Scope Creep**: M05 Farm Composer, M06 Master Data, and database schema modifications were not started. Downstream mock modules (Production, Stock, Purchasing, Sales, Money, Analytics, AI Assistant) remain untouched prototypes.
