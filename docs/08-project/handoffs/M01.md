## Objective
Establish the Next.js and TypeScript frontend application, design system language, responsive navigation shell, and realistic interactive MVP UX journeys for FarmOS, enabling subsequent engineering milestones (Codex M02+) to design and implement the backend against an understandable, validated user experience.

---

## What Was Implemented
- **Full Next.js 15 Web Application**: Structured monorepo workspace at `apps/web` with TypeScript, Tailwind CSS, Lucide React, and Jest.
- **Reusable Design System**: Built comprehensive UI primitives in `apps/web/components/ui/` with consistent status language, focus rings, accessibility tags, and mobile responsiveness.
- **Authenticated Application Shell**: Built responsive shell with top header, collapsible desktop sidebar, off-canvas mobile drawer, bottom mobile task bar, global search dialog (Cmd+K), exception notifications drawer, and low-input fast-log modal.
- **Complete MVP User Journeys (Mock State)**:
  - Account Sign-in and Sign-up prototypes with one-click demo persona quick fills (Farm Manager, Owner, Storekeeper, Field Worker, Vet) and error simulation.
  - Interactive multi-step Farm Composer onboarding (Organization → Farm → Enterprise/Poultry → Physical Houses in tree/list mode → Storage & Blueprint → Topology Review → Activation).
  - Home Operations Command Center answering "What needs my attention?" with exception summary, critical alerts, pending approvals, production snapshot, stock risk, and financial estimates.
  - Today Field Board with task filtering by role and rapid one-click logging triggers.
  - Multi-Farm Directory & Facility Overview detailing houses, storage warehouses, and biosecurity zones.
  - Poultry Production Directory & Flock Control Center Workspace (`/production/[id]`) with tabs for Overview, Daily Fast-Log, Mortality Journal, Feed Issues, Growth Curve, Vaccines, Harvest Schedule, and Cycle Economics.
  - Stock Inventory Ledger demonstrating distinct multi-state inventory balances (on hand, reserved, available, quality hold, expiring soon, incoming), lot-level FEFO expiry tracking, and warehouse capacity bars.
  - Purchasing & Procurement with requisitions, purchase orders, suppliers, and approval simulation.
  - Commercial Sales with customer contracts, harvest allocations, delivery dispatches, and invoices.
  - Financial Overview with cash balances, receivables, payables, and detailed broiler cost component breakdown.
  - Operational Analytics with planned vs actual growth curves, cumulative mortality projections, and cross-farm benchmarking.
  - Hermes AI Assistant conversation shell with verified source links and Human-in-the-Loop (HITL) action proposal cards.
  - System Settings shell covering organization profile, farms, RBAC team roles, localization preferences, and deterministic alert rules.
  - Operational Staff and Fixed Machinery/Asset registry shells.

## Major Components Created
- **UI Primitives (`components/ui/`)**:
  - `Button`, `IconButton`: standard variants (`primary`, `secondary`, `outline`, `ghost`, `danger`, `warning`), loading states.
  - `Input`, `Select`, `Textarea`: accessible form inputs with labels, helper texts, and validation errors.
  - `Card`, `CardHeader`, `CardTitle`, `CardDescription`, `CardContent`, `CardFooter`.
  - `Badge`, `StatusBadge`: product status badges (`ACTIVE`, `PLANNED`, `CRITICAL`, `WARNING`, `PENDING_APPROVAL`, `AVAILABLE`, `LOW`, `EXPIRING_SOON`, etc.).
  - `Modal`: accessible dialog with backdrop, escape key handler, and focus management.
  - `Tabs`, `TabsList`, `TabsTrigger`, `TabsContent`: tabbed navigation primitives.
  - `Table`, `TableHeader`, `TableBody`, `TableRow`, `TableCell`, `TableHead`: responsive data tables.
  - `MetricCard`: KPI card with values, delta trends, status tints, and subtitles.
  - `Alert`: inline warning/critical banners with dismiss triggers.
  - `EmptyState`: context-aware placeholder with CTA.
  - `Skeleton`, `CardSkeleton`, `TableSkeleton`: animated loading state placeholders.
  - `Breadcrumbs`: contextual hierarchy trail.
- **Application Shell (`components/shell/`)**:
  - `AppShell`: root layout orchestrating header, sidebar, mobile nav, search, and notification drawers.
  - `ShellProvider` / `context.tsx`: active tenant, active farm, active user persona, and search/notification state.
  - `Header`: farm switcher, global search button (Cmd+K), fast-log trigger, notification bell, and persona switcher.
  - `Sidebar`: desktop navigation grouped by Operations, Commercial & Finance, Farm Management, and Intelligence.
  - `MobileNav`: off-canvas mobile drawer and fixed bottom mobile bar (`Home`, `Today`, `Flocks`, `Stock`, `Menu`).
  - `GlobalSearch`: Cmd+K modal with quick search across flocks, houses, items, POs, suppliers, and tasks.
  - `NotificationDrawer`: slide-over panel for critical issues, pending approvals, and operational notices.
  - `FastLogModal`: low-input recording modal inheriting farm, house, and flock context without redundant re-entry.

## Known Limitations
- Session state and entity mutations are in-memory mock simulations and do not persist to a database.
- User persona switching operates client-side via React Context without server-issued authentication cookies/tokens.
- AI Assistant Hermes chat and HITL actions are structured client-side prototypes without live LLM or MCP infrastructure.

## Known Defects
None.

## Frontend Assumptions Needing Backend Decisions
- `ASSUMPTION-FE-001`: Farm summary UI assumes `id`, `name`, `code`, `location`, `enabledEnterprises`, `houses[]`, `warehouses[]`, `totalCapacity`, `activeCycleCount`, `criticalCount`, `warningCount`.
- `ASSUMPTION-FE-002`: ProductionCycle view model assumes `flockCode`, `startingBirds`, `currentLiveBirds`, `cumulativeMortalityPct`, `averageWeightGrams`, `fcr`, `livabilityPct`.
- `ASSUMPTION-FE-003`: Multi-state stock position view model assumes `onHand`, `reserved`, `available`, `qualityHold`, `expiringSoon`, and `expectedIncoming`.
